# XYZ龙门机械臂审计发现

## 已确认约束

- 用户明确要求底层操作指令均已测试，禁止修改。
- 已知三轴ID：X=`0x0100`、Y=`0x0200`、Z=`0x0300`；另有抓手ID `0x0400`。
- Motor线程优先级为工程最高，应继续由它独占CAN/ZDT动作。

## 初步发现

- `ZDT_drv.c/.h` 是协议驱动层。
- `ZDT_app.c/.h` 已有旧业务流程和全局位置变量，但需要完整审计其坐标语义、队列实现和安全边界。
- `Motor_thread_entry.c` 当前仍启用CAN台架周期测试帧，需要判断与正式机械臂队列的关系，但不在本任务中改动已验证协议。

## 完整审计结论

- 旧 `MotorMsg_t` 与 `g_motor_queue` 只有声明，没有创建、定义和消费逻辑，不能作为正式接口。
- 旧 `getMedicine()` / `storeMedicine()` 是忙等式长流程；如果由其他线程直接调用，会绕开Motor线程的CAN所有权，并可能永久等待当前工程中尚未定义的到位标志。
- `ZDT_MovePosition()` 的协议字段注明绝对位置，但底层兼容变量采用 `position += pos`；新接口不能把这些16位变量当作可信实时坐标，应维护独立的32位命令坐标快照。
- 当前回调只实现CANgaroo握手，没有在本仓库解析ZDT到位应答。为了不猜测或改写用户已验证的应答协议，新层只提供 `Gantry_NotifyAxisDoneFromISR()` 桥接口，后续由原有应答解析点调用。
- 正式机械臂运行时必须关闭每秒CAN台架测试帧，否则会污染电机总线；保留宏开关供台架需要时显式开启。

## 设计决策

- 新建独立 `gantry_robot` 应用模块，不改 `ZDT_drv.c/.h`。
- 调用方只投递命令，Motor线程通过 `Gantry_Service()` 串行调用ZDT底层。
- 多轴移动使用现有同步标志和 `ZDT_SyncTrigger()`；单轴直接启动。
- 位置在收到各轴到位通知后才提交为当前坐标；运动中另外保存目标坐标。
- 软限位、脉冲当量、方向和默认运动参数集中在配置结构中。
- 当前CAN中断IPL12高于FreeRTOS可安全调用API的范围，因此FromISR到位桥只写volatile轴标志，由Motor线程消费。
- 默认Z软限位采用0～420 mm保守值；真实行程和Z零位方向必须在有硬件时标定。
