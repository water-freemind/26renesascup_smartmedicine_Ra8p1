# 工程文档与 Git 归档计划

## 目标

整理比赛回来后的 RA8P1 工程状态，形成清晰的 Git 版本线、当前完成度、风险和后续任务说明；在保留完整备份的前提下，将单一归档提交拆成多个可审查提交并同步远程。

## 阶段

- [x] 阶段 1：检查工作区、分支、远程和提交数量
- [x] 阶段 2：盘点 README、docs 和历史专题文档
- [x] 阶段 3：重构工程总览的当前状态、版本线和文档索引
- [x] 阶段 4：同步 README 的入口信息（不写详细工作日志）
- [x] 阶段 5：静态一致性检查并汇报变更
- [x] 阶段 6：备份当前单提交归档点
- [ ] 阶段 7：按文档、工程配置、源码与工具资源拆分提交
- [ ] 阶段 8：校验最终树与远程同步

## 操作边界

- 保留源代码、RASC 配置和既有专题文档内容。
- 不删除历史提交；完整旧历史和当前单提交均保留备份标签及 bundle。
- README 只保留工程简介、结构、入口和常用命令；详细过程放入 docs。
- 所有新发现先写入 findings.md，阶段结果写入 progress.md。
