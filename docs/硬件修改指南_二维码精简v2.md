# 硬件修改指南 · 取药二维码精简（v2 变更）

> **目的**：本次云端把取药二维码的**编码内容**简化了（更短、更稀疏），以适配分辨率有限的摄像头。**你（MCU/硬件）的二维码解析代码需要跟着改**，否则扫到新码会解析失败。
>
> **范围**：本指南只讲这次"从旧格式到新格式"要改什么。**不并入**《硬件对接指南_MCU_LVGL.md》，那里更新后是权威，本文件是给改动时的对照。

---

## 一、变更摘要（云端已生效）

| 项 | 旧版本（云端之前的码） | 新版本（**现在的码**） |
| --- | --- | --- |
| 报文标识 `t` | `"PICK"` | `"P"` |
| 任务号 | `taskId` = `"PICK-PU-001"` | `q` = `"PU-001"` |
| 药品清单 | `items` = `[{drugId,…}]` | `i` = `[{d,…}]` |
| 每药字段 | `drugId/layer/x/w` | `d / l / x / w` |
| 二维码容错 | `M`（约15%） | **`L`（约7%）** |

**好处**：内容短 → 二维码模块数明显减少 → 对低分辨率摄像头更友好、更好扫。

---

## 二、新二维码格式（现在云端生成的样子）

```json
{ "t":"P", "v":1, "q":"PU-001", "i":[
  { "d":"DRG-1", "l":1, "x":66,  "w":72 },
  { "d":"DRG-2", "l":2, "x":140, "w":130 }
] }
```

---

## 三、字段映射（旧 → 新）★ 解析代码必看

| 含义 | 旧键 | **新键** |
| --- | --- | --- |
| 类型标识（固定） | `t` = `"PICK"` | `t` = **`"P"`**（值变了） |
| 版本 | `v` | `v`（不变） |
| 任务号 | `taskId`（`PICK-PU-001`） | `q`（`PU-001`） |
| 药品清单（数组） | `items` | `i` |
| 药品 id（核销用） | `drugId` | `d` |
| 所在层 | `layer` | `l` |
| x 坐标 mm（药位中心） | `x` | `x`（不变） |
| 药品宽度 mm | `w` | `w`（不变） |

> 上行协议**不变**：MCU 扫到后仍上报 `{"deviceId":"...","type":"PICKUP_SCANNED","drugId":"DRG-1"}`（回传的是 `d` 的值，字段名仍是 `drugId`）。

---

## 四、解析代码怎么改

**改动点**：判断类型用 `t=="P"`，循环读 `i[]`，取每项 `.d`（不再用 `items[].drugId`）。

```c
void on_qr_scanned(const char* qr_text){
    cJSON* root = cJSON_Parse(qr_text); if(!root) return;
    // 新格式：t="P"（取药码）；旧码 t="PICK"（见第五节兼容处理）
    if(strcmp(cJSON_GetObjectItem(root,"t")->valuestring,"P")!=0){ cJSON_Delete(root); return; }

    cJSON* list = cJSON_GetObjectItem(root,"i");          // 原来是 items
    for(int k=0;k<cJSON_GetArraySize(list);k++){
        cJSON* it = cJSON_GetArrayItem(list,k);
        int   layer = cJSON_GetObjectItem(it,"l")->valueint;    // 原来是 layer
        double x    = cJSON_GetObjectItem(it,"x")->valuedouble; // 不变
        const char* drug = cJSON_GetObjectItem(it,"d")->valuestring; // 原来是 drugId
        move_to(layer, x);                       // 定位取药
        send_pickup_scanned(drug);               // 上报仍用 drugId 字段名
    }
    cJSON_Delete(root);
}
```

## 五、⚠️ 兼容旧码（建议）

由于容错降到 `L` 且格式变了，若还有**旧二维码**（打印/遗留）未被使用，建议解析时**同时兼容新旧两种**，避免旧码失效：

```c
const char* t = cJSON_GetObjectItem(root,"t")->valuestring;
int is_pick = (!strcmp(t,"P")) || (!strcmp(t,"PICK"));   // 兼容新旧
if(!is_pick){ cJSON_Delete(root); return; }
// items 键：优先取 "i"，旧码没有再取 "items"
cJSON* list = cJSON_GetObjectItem(root,"i");
if(!list) list = cJSON_GetObjectItem(root,"items");
// 每项 d：优先 "d"，旧码回退 "drugId"；layer 同理 "l" / "layer"
```

> 云端现在**只产生新格式**；兼容旧格式仅为过渡。

---

## 六、低容错(L)对屏幕/打印的要求

- 容错 `L`（约7%）意味着**边角破损/遮挡更易失败**，因此：
  - 屏幕/打印显示时，保持**清晰的黑色内容 + 干净白底**，四周**留白边距**；
  - 二维码贴/拍时**平整无褶皱、不折叠**；
  - 摄像头对焦清晰、光照均匀——紧凑格式模块稀疏，普通对焦下反而更容易读通。

## 七、你需要动的地方小结

| 位置 | 是否要改 |
| --- | --- |
| QR 解码 → 类型判断 | 是（`PICK`→`P`） |
| 解码 → 循环键 `items` | 是（→`i`） |
| 解码 → 每项键 `drugId/layer` | 是（→`d/l`） |
| 上传 `PICKUP_SCANNED` | 否（上行字段不变，值从 `d` 取） |
| 依赖/接线/波特率 | 否 |
