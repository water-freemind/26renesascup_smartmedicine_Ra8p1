## A5. 2026-08-17 模块端实测记录与判定（用户万用表）

实测（模块引脚端，固件=官方基线 COM7=0x40/CLKRC=0x00）：

| 信号 | 读数 | 判定 |
| --- | --- | --- |
| VCC / RESET / PWDN | 3.3V / 3.3V / 0V | 供电、复位、掉电状态均正常，排除 PWDN 下电 |
| XCLK | 1.53V（≈半电源） | 25MHz 时钟到达模块并翻转 ✓（与 J-Link 一致） |
| PCLK | 1.48V（≈半电源） | 表笔读数像"翻转"，但 MCU 侧 J-Link 计数 0 跳变；同一条线两端不可能同时翻转/不翻转 → 判定该读数是悬空/漏电伪像，PCLK 实际无驱动 |
| HREF / VSYNC | 0.21V / 0.42V | 与 COM10=0x02（VSYNC_NEG 空闲高≈3.2V、HREF 占比明显非零）预期完全不符 → 无有效驱动，属悬空漏电读数 |
| 全部 16 根线通断 | 通过 | 排除断线/虚焊/连锡 |

结论：**控制通路全部正常、接线全部正常，但模块视频输出级（PCLK/HREF/VSYNC/D0-D7）整体为高阻无驱动**——故障定位在模块内部（板上 LDO 电源轨 1.8V/2.8V 异常、传感器模拟/时钟通路损坏或器件损坏）。此状态与"历史成功 SREC 在同一板复测同样无输出"一致。下一步优先实测模块板上可触及的 1.8V(DVDD)/2.8V(AVDD) 轨；无探点或探不到异常时，直接更换一块同型号 OV7725 模块做 A/B（模块价格低，是当前最快的排除手段）。

## A6. 2026-08-17 模块时钟链体检（慢速 XCLK A/B，验证模块是否真损坏）

用户暂无第二块模块，需进一步确认模块损坏与否。软件手段：把 XCLK 从 25MHz 降到 **100kHz** 并强制内部彩条（COM3=0x51 + DSP_CTRL3=0x20）。

- 原理：OV7725 的 PCLK/HREF 由 XCLK 经内部时钟链产生，SCCB 与寄存器访问与时钟无关。100kHz XCLK 下 PCLK≈200kHz、HREF≈87Hz，慢到 J-Link 引脚跳变计数器可直接捕获。
- 若 PCLK/HREF 跳变计数 > 0 → 模块时钟链与输出级存活（问题转向 25MHz 高速时钟下的驱动/时序，可试着把 XCLK 降到 12MHz 工作），若仍全 0 → 输出级/芯片死亡，确认需换模块。
- 构建入口：`-DRA8P1_CAMERA_SLOW_XCLK=ON`（同时强制 `CAMERA_SLOW_XCLK_HZ=100000`、`CAMERA_COLOR_BAR_DIAG=1`），默认 OFF；与 RTT-only 诊断固件配合使用。

## A7. 2026-08-17 突破：模块在 12.5MHz 下确认存活，断点收敛到 PCLK/HREF 两路

- 慢速 XCLK A/B 实机结论：**模块完全存活**。模块引脚端实测（13MHz XCLK 固件）：PCLK≈1.4V 波动（翻转中）、VSYNC≈3.2V（帧同步输出）、HREF≈1.57V（行有效输出）；SCCB、XCLK、PWDN/RESET、D0~D7、VSYNC 到 MCU 全部连通。
- **25MHz 下模块不启动输出**（模块端 HREF/VSYNC 仅 0.21/0.42V），13MHz 下全速输出 → 该模块的时钟链只在约 12~13MHz 工作。**正式基线已将 GPT10 XCLK 从 25MHz 改为 12.5MHz**（`configuration.xml` `module.driver.timer.period` 24000→12500，ra_gen period_counts 0xA→0x14，需在装有 RA8P1 device pack 的 RASC 上重新生成确认）。
- **剩余唯一断点：PCLK(HREF 两路从座子到 MCU 不通**：模块端有信号（1.4V/1.57V）、座子端电压正常（用户确认），但 MCU 侧 P414/P415 恒高（J-Link 45 次采样 0 跳变）。SCCB/XCLK/VSYNC/D 总线 14 路全通，唯独这两根断 → 优先怀疑自绘板座子↔MCU 走线/焊点或自绘板↔核心板 BTB 对应针脚接触不良。
- 待办：重新插拔模块与 BTB → 断电蜂鸣量 座子 PCLK/HREF 位置↔P414/P415 确认断点 → 飞线/补焊 → 烧录 12.5MHz 正式基线验证 `s_dbg_ceu_frame_cnt`。

## A8. 2026-08-17 帧率调优结论：~10 FPS 为当前模块物理上限

- 帧率与 XCLK 严格线性（实测 0.8 FPS/MHz：12.5MHz→9.9FPS；历史 25MHz 正常模块≈20FPS）。
- XCLK 提升 A/B（烧录校验 GTPR 确认频率真实生效）：14.7 / 16.7 / 20.9 / 25MHz **全部不启动（0 帧）**，12.5 / 13.2MHz 正常 → **该模块时钟输入通路已退化，XCLK 硬上限约 13~14MHz**。
- 时序寄存器调优无效：VTS(0x2D/0x2E) 写 320 无变化；COM5(0x0E) 写 0xF0（最低分频档）无变化；HTS/VTS 读回均为 0（传感器变体使用固定内部时序链，寄存器不生效）。
- **结论：当前模块 ≈10 FPS 即上限**，对二维码扫描（静态场景）足够；若需更高帧率需更换状态正常的 OV7725 模块（25MHz 下可达 20FPS+）。
- 调优手段保留为编译选项（默认 OFF）：`RA8P1_XCLK_KHZ`、`RA8P1_CAMERA_VTS`、`RA8P1_CAMERA_COM5`；正式基线维持 XCLK=12.5MHz、COM5=0xF5、VTS 默认。

# 摄像头万用表排查清单（2026-08-17，优先级最高）

> 背景：官方基线固件（COM7=0x40/CLKRC=0x00/CEU 边沿 rising）已烧录并运行；J-Link 实测确认 MCU 侧 XCLK 在 P109 正常翻转、OV7725 SCCB 全部正常、无软睡眠，但 P414(PCLK)/P415(HREF)/P708(VSYNC) 无驱动（直接 PIDR 与计数器读数矛盾=悬空）。软件侧已穷尽，下一步用万用表在硬件上定位"模块端到底有没有输出/线通不通"。手头只有万用表时的测量顺序如下。

## A0. 首位嫌疑：PWDN（模块下电）与 RESET 电平核对（2026-08-17 新增）

- MCU 侧官方固件实测 `s_dbg_power_levels=0x02` = MCU 的 PWDN(P709) 输出 **0V**、RESET(P710) 输出 **3.3V**。
- 用户在模块引脚端实测：**RESET=3.3V ✓、PWDN=3.3V ✗**。OV7725 PWDN 高电平=掉电；掉电态下 SCCB 寄存器仍可读（解释 PID/VER 全通），但视频输出级关闭（解释 PCLK/HREF/VSYNC/D0-D7 异常）。
- **结论优先级最高：先验证 PWDN 这根线**：断电后用蜂鸣档量 P8 pin6（P709）到模块 PWDN 引脚通断；再上电同时量 MCU P709 焊点（应 0V）与模块 PWDN 脚（实测 3.3V）。若两端电平不一致 = 该线断线/虚焊/错接到别的脚，修复或飞线后摄像头可能直接恢复输出。
- 若 PWDN 确实连通但模块端仍 3.3V，则模块内部 PWDN 极性/装配与官方 P8 定义不同，需按该模块实际 20pin 定义重新核对接线。

## A. 上电测量（板已运行本固件，等待 3 秒后测量）

万用表拨到 **DC 电压档**（20V 档）。数字表对几十 MHz 方波只能读平均值：50% 占空比信号≈电源一半。P8 座子（2×8）引脚定义见本文档第 4.5 节；能探到模块引脚/焊点优先探模块端，探不到就探 P8 座子针脚。

| 测量点（模块端优先） | 期望值（模块正常输出） | 故障含义 |
| --- | --- | --- |
| 模块 VCC 对 GND | ≈3.3V | 偏低/0V=供电问题 |
| PWDN (P8 pin6 → P709) | ≈0V | 若≈3.3V=模块被掉电 |
| RESET (P8 pin15 → P710) | ≈3.3V | 若≈0V=模块被复位 |
| XCLK (P8 pin16 → P109) | ≈1.6V（25MHz 50% 占空比平均） | 0V/3.3V=无时钟 |
| PCLK (P8 pin13 → P414) | ≈1.6V（约48MHz 闪烁） | 0V 或 3.3V 不动=无像素时钟输出 |
| HREF (P8 pin4 → P415) | 明显非 0（约 1.8V±，行有效占比高） | ≈0V 不动=无行同步 |
| VSYNC (P8 pin2 → P708) | ≈3.2V（VSYNC_NEG 空闲高、帧首脉冲低） | ≈0V 不动=无帧同步 |
| D0~D7（P8 pin5/8/7/10/9/12/11/14） | ≈1~2V 之间波动 | 全 0/全 3.3V 不动=无数据输出 |

判定：

1. 模块端 XCLK≈1.6V、PCLK≈1.6V、HREF/VSYNC 有正常值 → **模块在输出**，问题在模块→MCU 的这几根线/接触。
2. 模块端 XCLK≈1.6V 但 PCLK/HREF/VSYNC/D0-D7 全为固定电平 → 模块被配置进无输出状态或输出级异常；先复查 PWDN/RST 实测电平与模块 3.3V 供电（含滤波电容是否虚焊）。
3. 模块端连 XCLK 都不是 1.6V（0V 或 3.3V）→ 时钟都没到模块，重点查 P109 到模块的走线/座子接触。
4. 若万用表有 **Hz 频率档**：直接测 XCLK 期望≈25MHz、PCLK 期望≈48MHz，比平均值判断更准（部分表上限只到 10~20MHz，读不到属正常，以电压平均值为准）。

## B. 断电通断测量（必须断电后进行；用蜂鸣/二极管档）

从 **P8 座子 MCU 侧焊点** 到 **模块引脚**（或模块排线两端）逐根量通断，重点核对：

- P109↔XCLK、P414↔PCLK、P415↔HREF、P708↔VSYNC、P400/P401/P405/P406/P700/P701/P702/P703↔D0~D7、P709↔PWDN、P710↔RESET、P409↔SDA、P410↔SCL。
- 判据：同一条线两端应 <1Ω（蜂鸣响）；相邻脚之间不得相互导通（防止连锡/短路）；PWDN/RESET 若在座子内部有下拉/上拉（模块自带时）读数会不同，先看是否有稳定通断再下结论。
- 此步同时验证 P8 座子焊接质量：MCU 侧 P414 焊点若到座子针脚都不同，说明座子虚焊。

# RA8P1 硬件总览

## 2026-08-16 最新联调结论

- CST816S 触摸芯片已经能够正常通信和产生坐标；本轮确认的剩余问题是软件坐标方向，已在 LVGL 层修正为 `X=639-raw_y`、`Y=raw_x`，对应 640×480 横屏画布。
- 扫描页会启动 OV7725，摄像头与触摸共用 IIC0（P409/P410）。摄像头初始化现增加总线空闲检查和失败熔断，避免摄像头失败重试把共享 SDA/SCL 故障持续放大；这不改变现有硬件接线。
- 若进入扫描页后 SDA 持续为低、SCL为高，不能通过软件把 SDA 强推为高；I2C 为开漏结构。当前软件会先将 OV7725 置 `PWDN=1/RST=0`，再重建 IIC0。若断电重启后仍复现，下一步是实现标准 9 个 SCL 恢复脉冲并发送 STOP；若仍不能释放，则需补接摄像头/触摸控制板的硬件复位或检查上拉与器件供电。
- 标准 9 脉冲恢复现已实现：IIC0 Close 后，P409/P410 暂时切换为 GPIO，SCL 低/释放高循环最多 9 次，生成 STOP 后恢复 P409/P410 的 IIC 复用。若恢复计数增加但 SDA 仍低，说明外部器件持续拉低或没有有效上拉，软件无法再安全解决，必须检查摄像头/触摸板供电、上拉和硬件复位线。

## 2026-08-16 摄像头优先联调边界

- 当前实测事实：触摸芯片供电 3.3V，进入扫描页后 SDA=0V、SCL为高，且断电重启与带电 reset 后仍保持；说明至少有一个外部 IIC 从机持续下拉 SDA，不能继续假设只是 MCU 外设状态残留。
- 后续先断开屏幕触摸联调，把 OV7725 单独作为目标验证。摄像头成功条件依次为：SDA/SCL 空闲高电平 → OV7725 `0x21` ACK → PID/VER 读回 → 初始化表完成 → CEU 有帧结束 → RTT 预览有有效图像。
- 在摄像头独立验证完成前，不再把屏幕 CST816S 与 OV7725 同时接入 IIC0；这样可以区分“摄像头器件/复位导致 SDA 拉低”和“触摸控制器自身占线”。

## 3. 自绘板审查结论

| 等级 | 区域 | 结论与修改要求 |
| --- | --- | --- |
| A | 电机供电 | 禁止用 ATX `+12 V` 与 `-12 V` 跨接成电机 24 V。`-12 V` 不是电机功率轨，还会让非隔离 CAN 产生危险地电位偏移。改用独立 24 V 电源；若驱动允许，也可使用 `+12 V/GND` |

## 5. CAN 物理层

TJA1042TK/3 的 pin1～8 是 TXD、GND、VCC、RXD、VIO、CANL、CANH、STB。当前 `VCC=5 V`、`VIO=3.3 V`、STB 10 kΩ 下拉方向正确，裸露 EP 必须接地。

60.4 Ω + 60.4 Ω 分裂终端等效约 120.8 Ω，中点 10 nF 到地合理，但一条总线只能在两个物理端点终端匹配。NUP2105L 类型合适，应紧靠外部端子，地回路尽量短。外部端子推荐 CANH/CANL/GND。

ZDT CAN 协议、报文和到位应答已经实测通过，本次不修改协议代码，只整改物理层。

### 8.3 当前三组排线的最简点屏方案

当前实物计划只连接核心板、WLK 控制/转接板和屏幕之间已有的三组排线。对 WLK2802MIPI-15P V2（ST7701S）而言，可先按下列最小链路进行显示验收，不把额外飞线作为首次点屏的前置条件：

| 信号组 | 首次点屏要求 | 说明 |
| --- | --- | --- |
| 3.3 V 与 GND | 必须 | 必须先核对排线方向、针号和控制板实际供电要求，所有板卡共地 |
| MIPI DSI Clock ± | 必须 | 差分极性不可交换 |
| MIPI DSI Lane0 ± | 必须 | 当前面板资料指定 DSI 1 Lane，RASC 保持 1 Lane |
| MIPI DSI Lane1 ± | 软件不使用 | 即使排线物理带出，也不能因此把 RASC 改为 2 Lane |
| SDA/SCL | 保留现有连接 | 24pin 转接板已经带出；是否供控制板或触摸使用，待实物确认，ST7701S 的显示初始化命令本身由 MIPI DSI DCS 发送 |
| LCD_TE | 不要求 | 当前采用 MIPI Video Mode，驱动不得等待 TE 信号 |
| LCD_RST/P_RST | 当前强烈建议核对/接出 | 原厂 Linux 驱动允许 reset GPIO 缺省，但本次实机低功耗初始化卡忙；若转接板未自动释放 P_RST，单发 DCS `0x01` 不能替代硬件复位，必须补 P_RST 或确认控制板上电复位电平 |
| LCD_BL/BLC | 条件性可不接 | 只有控制板能够自动或固定开启背光时才可省略；必须通过上电观察确认 |
| TP_INT/TP_RST | 显示不要求 | 已确认触摸方案为 CST816S；当前两根线未接，只影响触摸，显示应单独验收 |

无硬件复位线时，面板初始化至少执行：发送 DCS `0x01`（Software Reset）→等待约 120 ms→发送 ST7701S 厂商初始化表→发送 `0x11`（Sleep Out）并等待约 120 ms→发送 `0x29`（Display On）。`st7701s_panel_board_reset()` 可保留为空的板级钩子，但软件复位不能省略。

首次上电先只判断背光：屏幕出现均匀灰亮或可见漏光，只能说明背光供电/控制有效；完全无光则优先检查供电与 BLC/LCD_BL。有背光但无图像时，先查 FPC 方向、DSI 差分映射、Clock/Lane0 极性、3.3V/GND 和 P_RST，再查像素时钟与初始化命令。原厂树莓派资料的 reset GPIO 是 optional，但本板控制板的上电默认电平尚未实测，不能直接假定软件复位一定可靠。

### 8.4 2026-08-16 实机诊断与三组排线结论

- 原厂 `raspberry_dsi_demo` 的 `README_zh.md` 明确将 W280BF036I 定义为 `480x640 / DSI 1 Lane / 24p`；因此工程 RASC 必须使用 1 Lane。
- 物理三组差分对应 `DSI_C±`、`DSI_0D±`、`DSI_1D±`。本屏协议只使用前两组（Clock + Lane0）；第三组 Lane1 即使已接入，也不能在 RASC 中启用。
- 当前烧录的 1 Lane 固件已完成 ST7701S 初始化、`RM_LVGL_PORT_Open()` 和纯色帧缓冲写入；此前 `SQ0RUN/SQ1RUN` 卡忙问题已经通过正确包类型和 Sequence 完成等待修复。
- P_RST 测得 3.3V，通常表示复位已释放；但该线当前未接 MCU GPIO，软件只能发送 DCS `0x01`，不能主动拉低 P_RST 做硬件复位。若可视显示仍失败，建议下一版或临时飞线将 P_RST 接到独立 GPIO。
- 排查顺序固定为：`P_RST` 是否被拉低或悬空 → FPC pin1 方向 → `DSI_C+/-` 与 `DSI_0D+/-` 是否同名同极性 → 3.3V/GND → 线缆连续性/接触 → 再查像素时钟和初始化表。不要先把 Lane 改成 2。
- 背光独立于 DSI 数据，背光亮而无图像与当前诊断一致；在命令链路通过前不能判定屏幕或 LVGL 已成功。
- 原厂树莓派模式时钟为 22572 kHz（550×684×60 Hz），当前 RASC 生成配置为 24 MHz（约 63.8 Hz）。这属于低优先级的后续时序优化，不能解释当前初始化命令通道卡忙；链路恢复后再根据实物稳定性调整。

## 11. 新板上电测试顺序

1. 空板断电查短路，核对所有连接器 pin1 和关键网络通断。
2. 不插核心板、ESP、电机，限流验证 3.3 V、5 V、12/24 V。
3. 验证 PS_ON#、保险和电源指示。
4. 插核心板但断开外设，检查电流并验证 J-Link 下载。
5. 单测 CAN：500 kbit/s，CANH/CANL/GND，终端只在两端；沿用已验证 ZDT 协议。
6. 单测 ESP：先查启动脚，再从 115200 bit/s 做 AT 通信和 Wi-Fi 发射压降测试。
7. 单测摄像头，复用当前 OV7725 灰度采集和 RTT 预览基线。
8. 单测 MIPI：背光/复位→纯色→LVGL→触摸→摄像头预览。
9. PWM 空载用示波器确认频率/占空比，再接驱动级；注意 P903/P904 同频。
10. 最后接电机功率，在限流、保险和急停有效时逐步加载。

## 15. 核心板电源树与USB接口

- `VCC_5V`：由JDBG调试USB路径或BTB输入，经保护路径供电。
- `VIN_5V`：JUSB或BTB输入侧5V，供板上DCDC/LDO和外设。
- `VSYS_3V3`、`VCC`、`VCC2`：3.3V数字与I/O电源域。
- `VCC_1V8`、`VCC18_MIPI`、`AVCC_MIPI`：1.8V和MIPI电源域。
- `VCC_USB`、`VCC_USBHS`、`AVCC_USBHS`：USB专用电源域。
- `AVCC0`、`VREFH0/VREFL0`、`AVSS0/VREFL`：模拟电源和参考域。
- `VBATT`：备份电源域。

5V转3.3V使用 `ISL80102IRAJZ`，1.8V使用 `ISL80505IRAJZ-T`，USB限流使用 `AP22615AWU-7`。USBHS Type-C控制器为 `FUSB303BTMX`，VBUS开关为 `LPW5209AB5F`。相关引脚与I2C、摄像头等功能复用时，必须结合实物0Ω装配判断。

## 17. 外部存储与GUI容量

目标器件 `R7KA8P1KFLCAC` 内部提供1 MiB Code MRAM，但没有Data Flash。固定程序、字体、图标和LVGL页面常量可由链接器直接放入Code MRAM；运行时若要擦写内部MRAM必须使用FSP `r_mram`，并预留独立分区、从RAM执行写入流程及处理写入期间的中断。内部MRAM不适合作为药品图片、取药流水或高频库存数据仓库。

板载串行Flash候选映射为P107=CE、P808=SCK，P100/P803/P103/P101为数据及WP/HOLD，实际使用前需确认U3/U6装配。SDRAM适合LVGL帧缓冲、图片解码和摄像头缓冲，但不能代替程序Flash；药品图片、字体和数据库应优先放microSD或外部串行Flash。

当前RASC活动Pin配置已经包含OSPI0的CS0、SCLK和SIO0～SIO3复用，但还没有 `r_ospi_b` 驱动实例。确认实际焊接芯片后，软件首测必须先读取JEDEC ID并根据W25Q256或AT25SF256的数据手册选择命令、状态寄存器、QE位、页大小和擦除粒度，不能仅凭两者都是256 Mbit就共用未经验证的初始化表。

建议固定控件代码留在片内Flash，药品图片放microSD；常用字体和图标根据启动速度与可靠性决定放片内或外部Flash。

### 摄像头优先测试的 IIC0 隔离边界（2026-08-16）

- OV7725 与触摸控制器共用 P409/SDA、P410/SCL 在地址层面可以共存，但 I2C 是开漏总线：任一外部器件或异常事务持续拉低 SDA，另一个设备都无法通信。

- 摄像头单独验收前，屏幕触摸控制板建议断开或至少不让其参与 IIC0；测量 P409/P410 空闲均应接近 3.3 V。SDA 不能由 MCU 推挽拉高，必须依靠外部上拉和从机释放。

## 2026-08-16 触摸接口验收边界

- 屏幕资料中的触摸接口为 `I2C1_SDA`、`I2C1_SCL`、`TP_INT`、`TP_RST`；这些信号与 MIPI 时钟/数据差分线不是同一类连接。
- 触摸芯片判定为 **CST816S**：屏幕资料目录内的 `WLK2802MIPI-15P V2_LVGL_Widgets Touch 触摸.bin` 含有 `esp_lcd_touch_new_i2c_cst816s`、`touch_cst816s_read_id`、`esp_lcd_touch_cst816s_read_data` 等 CST816S 驱动符号。该证据比仅凭接口名称推测更可靠。
- CST816S 软件初始参数按 7-bit I2C 地址 `0x15`、单点触摸规划；最终验收必须实际读取芯片 ID，不能仅凭默认地址判定焊接正确。TP_INT/TP_RST 未接时可做轮询读 ID，但不能做完整中断和复位测试。
- 当前工程已生成的摄像头 I2C 为 `g_i2c_master0/IIC0`，使用 P409/P410，地址配置为 OV7725 的 `0x21`。触摸若共用 P409/P410，地址 `0x15` 与 `0x21` 不冲突，但软件必须串行化摄像头 SCCB 与触摸访问，避免同时操作同一 IIC 控制器。
- 若 RASC 改为独立 IIC1，仍需先确认 RA8P1 的实际引脚复用和板上 `I2C1_SDA/SCL` 网络；本轮不改 RASC，而是复用已经验证的 IIC0。`src/driver/src/camera_drv.c` 已增加 FreeRTOS 互斥，CST816S 访问期间临时切换到 `0x15`，事务结束后恢复 OV7725 的 `0x21`，因此两个设备不能在同一时刻访问总线。
- 当前触摸代码使用轮询，不要求 TP_INT/TP_RST：LVGL 输入回调读取 CST816S 的手势、触点数、X/Y 寄存器；没有 TP_INT 时会增加 I2C 访问次数和响应延迟，没有 TP_RST 时无法由 MCU 单独复位触摸芯片。若后续出现芯片死锁、上电状态不确定或需要低功耗唤醒，仍建议补接 TP_RST；若需要中断降负载，再补接 TP_INT。独立轮询已实测 `pressed=1`、`fingers=1`、`X=229`、`Y=354`。
- 2026-08-16 软件协议复核：CST816S 参考实现使用 `i2c_master_transmit_receive`，因此 RA8P1 端已将触摸寄存器访问改为 IIC0 的重复 START；摄像头 SCCB 仍保持原有 STOP 分隔事务。该改动只影响总线事务协议，不改变排线、引脚或 RASC 配置。
- 触摸验证时必须保证 SDA/SCL 有 3.3V 上拉、与摄像头共地，并先单独观察 `0x15` 是否 ACK；`0x15` 与 OV7725 `0x21` 不冲突，所以共线在电气地址层面可行。真正的软件约束是共享 IIC0 的互斥访问，不能让摄像头线程和 LVGL 输入回调并发调用 FSP IIC。
- 共享 IIC0 的可靠性规则已固化：所有摄像头和触摸事务都必须经过 `camera_i2c_write_at()`/`camera_i2c_read_at()`；总线互斥覆盖“切换从机地址→完整事务→恢复 OV7725 地址”全过程。初始化由独立互斥保护，完成信号在新事务前清空，5 秒无回调时执行 `R_IIC_MASTER_Abort()` 并清零状态机，避免一次异常访问永久阻塞另一设备。

### 2026-08-16 实机触摸诊断结论

- J-Link 实际读取到：`probe_ok=0`、`probe_fail=114`、`error_reg=0xA7`、`last_reg=0xA7`、`read_ok=0`，且 IIC0 互斥/超时/地址切换错误均为 0。

- 在 `probe_ok` 成功前，不修改坐标旋转，也不把问题归因于 LVGL。软件侧的共享 IIC0 和连续读取修正已编译完成；下一次烧录后仍先看 `0x15` ACK 和上述诊断值。
## 2026-08-16 CST826 实机总线结论

- 触摸芯片型号已由用户确认是 **CST826**，不是此前文档中暂写的 CST816S。CST826 采用 I2C，常用 7 位地址 `0x15`；资料/公开驱动定义的关键寄存器为芯片 ID `0x11`、触点数量 `0x02`、触摸数据起始 `0x03`。
- 实机 J-Link 读取 IIC0 状态：`ICCR2.BBSY=1`，`ICCR1.SDAI=0`、`SCLI=1`。这表示 SDA 被持续拉低，属于总线物理占用；IIC0 的 IRQ 8~11 已使能，不能再归因于 RASC 中断漏配置。
- 当前只接 SDA/SCL、未接 `TP_INT/TP_RST` 时，正常轮询理论上可工作；但是一旦 CST826 因异常事务保持 SDA 低电平，MCU 没有 `TP_RST` 就无法主动复位触摸芯片。建议重新打板时至少引出 `TP_RST`，`TP_INT` 可选。
- 摄像头 OV7725 与触摸 CST826 共用 IIC0 在地址层面可行（OV7725 `0x21`、CST826 `0x15`），但必须保证总线空闲高电平、共地、3.3V上拉和互斥访问；当前软件已实现互斥与故障恢复。
## 2026-08-16 CST826 触摸事务修正

- 用户重新接入屏幕排线，摄像头 RTT 修复暂时停止，先完成屏幕触摸验收。
- 触摸驱动原来调用 STOP 分隔的 IIC 读取 helper，与 CST826 的“寄存器地址写入后重复 START 再读”协议不一致；现已统一改为 `camera_i2c_read_block_at()`，覆盖 ID/固件版本和触点坐标读取。

# 2026-08-16 软件联调补充：摄像头与触摸共用 IIC0

- 硬件事实不变：OV7725 使用 `0x21`，CST816S 使用 `0x38`，两者共用 P409/SDA、P410/SCL；地址不冲突，但必须串行访问。
