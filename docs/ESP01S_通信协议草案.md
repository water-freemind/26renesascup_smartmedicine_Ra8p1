## 1. 物理层（已就绪，待补 UART 栈）

- ESP-01S 通过 **SCI9 UART** 与 RA8P1 相连：P208 = RXD9（ESP TXD）、P209 = TXD9（ESP RXD）。
- configuration.xml 中 SCI9 引脚已复用为异步 UART，但**尚未添加 r_sci_b_uart 栈实例**（无 `g_uart9`），需 RASC 新增后再写驱动。
- 建议波特率 **115200 8N1**（ESP-01S AT 固件默认；若模块固件是 9600 旧版，按模块实际调整）。
- 电气注意：ESP-01S 是 3.3V 模块，P208/P209 与模块同域 3.3V，无需电平转换；模块启动时 GPIO0 拉低进入烧录模式，正常运行悬空/上拉。

## 2. 分层

```
┌──────────────┐   JSON 行协议（\n 结尾，≤1KB/条）   ┌──────────────┐
│   RA8P1 MCU  │ ──────────────────────────────────▶ │   网页端     │
│  (TCP client)│ ◀────────────────────────────────── │  (TCP server)│
└──────────────┘           AT 命令透传               └──────────────┘
       ▲                                                  ▲
       │ r_sci_b_uart (SCI9, 115200)                       │ 用户自建服务器/云主机
       ▼                                                  ▼
   ESP-01S (STA 模式连 WiFi)                   固定公网 IP/域名 + 端口
```

- **设备是 TCP 客户端**：ESP-01S 无公网地址，必须由设备主动连接网页服务器（固定公网 IP/域名）。
- 网页端需要：监听 TCP 端口（如 8080），按行读取 JSON，按 `t`/`cmd` 字段分发。

## 3. 传输层（二选一，建议 A）

### A. TCP 长连接 + JSON 行协议（推荐）
- 设备开机连 WiFi 后建立 TCP 长连接，断线指数退避重连（1s/2s/4s…上限 60s）。
- ESP-01S 用透传模式 `AT+CIPMODE=1`，MCU 只收发裸 JSON 行，协议解析最简单。
- 心跳：设备每 30s 发 `{"t":"heartbeat",...}`，服务器 90s 无心跳判定离线。
- 优点：实时性好（指令下发秒级）、实现简单；缺点：需服务器保活管理。

### B. HTTP 轮询
- 设备定时 `GET /api/poll` 取指令、`POST /api/report` 上报数据（JSON body）。
- 优点：网页端只需 HTTP 接口（任何语言框架都有）；缺点：下发延迟=轮询周期（建议 2~5s），且 ESP-01S 逐条 AT 命令解析 HTTP 响应较繁琐。

> 若网页端尚未定型，**先按 A 定消息格式**（纯 JSON 行），B 只需把"行"包进 HTTP body，字段不变。

## 4. 消息格式（应用层，与传输层无关）

统一约定：
- 每条消息是一行 **UTF-8 JSON**，以 `\n` 结尾（无 `\r`）。
- 公共字段：`t`（设备→服务器消息类型）/ `cmd`（服务器→设备指令类型）、`ts`（Unix 秒，可选）、`dev`（设备 ID，默认 `"sm01"`）。
- 所有字段名用驼峰小写；时间统一 Unix 秒。

### 4.1 设备 → 服务器（上报）

| t        | 含义         | 示例 |
|----------|--------------|------|
| heartbeat| 心跳+状态     | `{"t":"heartbeat","dev":"sm01","ts":1789000000,"wifi":-55,"fps":9.9,"cam":"on"}` |
| scan     | 扫码结果     | `{"t":"scan","dev":"sm01","code":"MED-001","ok":true,"ts":1789000001}` |
| pickup   | 取药记录     | `{"t":"pickup","dev":"sm01","med":"MED-001","name":"阿莫西林","qty":1,"user":"u1","ts":1789000002}` |
| stock    | 库存快照/变更| `{"t":"stock","dev":"sm01","items":[{"id":"MED-001","name":"阿莫西林","qty":120,"exp":"2027-01-01"}]}` |
| log      | 日志         | `{"t":"log","dev":"sm01","level":"info","msg":"摄像头启动","ts":1789000003}` |
| alarm    | 告警         | `{"t":"alarm","dev":"sm01","level":"warn","msg":"库存不足 MED-001","ts":1789000004}` |

### 4.2 服务器 → 设备（下发）

| cmd      | 含义         | 示例 |
|----------|--------------|------|
| restock  | 补货指令     | `{"cmd":"restock","med":"MED-001","qty":50}` |
| reboot   | 重启设备     | `{"cmd":"reboot"}` |
| sync     | 触发全量上报 | `{"cmd":"sync"}` |
| ack      | 对上报的应答 | `{"cmd":"ack","t":"stock","ok":true}` |

### 4.3 约定
- 设备收到 `sync` 后依次回 `heartbeat`+`stock` 全量快照。
- 设备收到未知 `cmd` 回 `{"cmd":"ack","ok":false,"msg":"unknown cmd"}`。
- 扫码成功 1s 内自动回 `scan`；失败不报（避免刷屏），由网页端超时提示。
